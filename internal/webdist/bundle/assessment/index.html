    GitHub-Native Passport Assessment

    The passport measures observable research-computing behavior through one permanent public draft pull request. It is open-book and iterative; it does not reward memorizing commands.

    View exact sourceReturn to my dashboard

    The passport measures observable research-computing behavior through one permanent public draft pull request. It is open-book and iterative; it does not reward memorizing commands.

    Four-Repository Model#

    Repository Visibility Purpose
    IDEALLab/onboarding-IT lab handbook policy Curriculum, site, generator source
    soheylm-passport-sandbox/passport-exercises public Fictional exercises and PR destination
    soheylm-passport-sandbox/gh-passport public Cross-platform GitHub CLI extension releases
    soheylm-passport-sandbox/onboarding-control private Enrollments, assignments, controller, operations, registry

    Each learner owns a normal personal fork: username/passport-exercises. No student repository is created inside IDEALLab, and students receive no organization repository-creation right.

    Assessment Flow#

    trusted enrollment in onboarding-control
  + learner public fork / onboarding/<username>
  + one draft PR into soheylm-passport-sandbox/passport-exercises
  -> fork ancestry, immutable identities, route, branch, and base verified
  -> exact SHA checked without network or credentials
  -> deterministic Check Run and one updated PR comment
  -> learner revisions
  -> one automatically requested final human review
  -> minimal private completion record

    Public Evidence Boundary#

    The PR may contain only fictional scenarios, bounded code, safe Slurm fixtures, and sanitized explanations. It must never contain:

    • passwords, tokens, private keys, recovery codes, or ETH/private identifiers;
    • real logs, broad job history, private screenshots, or personal information;
    • unpublished research data, project details, datasets, checkpoints, or results;
    • complete AI chat transcripts or paid-service account information.

    A secret scan stops before parsing, execution, or optional AI review. A real incident uses private lab channels, not the assessment PR.

    Authority#

    • The learner owns every answer, command, diff, and correction.
    • The local browser remembers navigation only.
    • The public fork and PR are an audit trail, not pass authority.
    • The private controller App publishes objective status for an exact SHA.
    • The assigned reviewer may approve only that exact SHA.
    • The private registry stores only the minimal endorsement record.

    A merge, label, learner workflow, local checkbox, similarly named Check Run, or AI response cannot award completion. Learners are told not to merge or close the permanent assessment PR.

    Submission Loop#

    Every mission shows the exact evidence path and standard Git loop. After a push, the scheduled controller responds within its polling window. When all deterministic gates pass, it requests one route-level reviewer automatically; the learner never needs a reviewer to remain online.
