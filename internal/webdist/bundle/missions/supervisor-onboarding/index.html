    Short explanationConcept, example, common mistake, and recovery

    Outcome#

    Define responsibilities, owners, systems, data locations, minimum access, and review dates for a new researcher.

    Concept#

    Technical instructions cannot resolve missing ownership and access decisions. Assigning every student the same route also wastes time and leaves role-specific risks unaddressed.

    Worked Example#

    The plan grants no access by implication and clearly separates training completion from authorization.

    Check these points:

    • Does passing the passport authorize system access? No. Access requires a separate owner-approved operational decision.
    • What access should be requested? Only what the person needs, with an owner and review or end date.

    Common Trap#

    Treating a passed training mission as authorization to access a system or dataset.

    If Blocked#

    Do not grant broad access while waiting for a decision. Record the blocker and obtain the information owner, system owner, or lab owner decision. Use lab IT policy for escalation.

    Understand Before Accepting AI Output#

    An agent may format the packet but cannot authorize access, classify data, approve AI services, choose compute shares, or create policy exceptions.

    Do the mission

    Complete this mission

    Pass: 100% + every safety item
    Action

    Review a fictional researcher onboarding case and choose the route, owners, access, locations, dates, and approval boundaries.

    Expected

    Every requested capability has a reason, owner, location, review date when needed, and separate operational approval.

    Follow in order

    Steps

    Training completion never grants system access. Every operational permission needs a separate owner decision.

    1. 01

      Define the person's work

      This browser

      List the fictional researcher's real responsibilities: code, data stewardship, Euler CPU or GPU, Blade, AI tools, supervision, or none of these.

      Expected
      The route contains only relevant responsibility tracks and their prerequisites.
      Continue when
      Map each responsibility to a system.
      If not
      Clarify the project role before requesting access.
    2. 02

      Name decision owners

      This browser

      For each repository, dataset, storage area, compute share, software license, and AI service, name who approves access and who supports it.

      Expected
      Every requested system has an accountable owner.
      Continue when
      Request minimum access.
      If not
      Do not grant access by implication or convenience.
    3. 03

      Limit scope and duration

      This browser

      Request only the permissions needed for the stated task. Add a review or end date for temporary roles, guests, and project-specific access.

      Expected
      No broad or permanent access lacks a task and review date.
      Continue when
      Name authoritative code and data locations.
      If not
      Reduce the request or obtain a documented owner exception.
    4. 04

      Document working locations

      This browser

      Record where code, durable data, temporary data, computation, and handover records belong.

      Expected
      The researcher does not need to guess between laptop, GitHub, NAS, Blade, and Euler.
      Continue when
      Separate training from provisioning.
      If not
      Resolve the authoritative location before data is created.
    5. 05

      Track operational approvals separately

      This browser

      Record each access request and owner decision outside the public assessment. A passed mission is evidence of training, not authorization.

      Expected
      Provisioning status and Passport status are separate.
      Continue when
      Complete the fictional packet questions.
      If not
      Do not activate access solely because training passed.
    6. 06

      Review the onboarding packet

      This browser

      Use the scenarios below to check responsibilities, owners, minimum access, locations, dates, and help paths for the fictional case.

      Expected
      Every scenario has one explicit, least-privilege decision.
      Continue when
      Run Check my work.
      If not
      Add the missing owner or decision before approval.
