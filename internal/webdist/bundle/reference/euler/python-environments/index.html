    Python Environments On Euler

    View this page on GitHubReturn to my progress
    Before running a command

    A command is a line of text that tells a computer to do one task. You paste it into a terminal, the text application used for commands. A shell is the part inside that application that reads the command. PowerShell, zsh, and Bash are shells. Open only the application named for your computer below; it starts the correct shell automatically. You do not need to install a separate Bash or zsh application.

    • Windows: press the Windows key, type PowerShell, and open the result named PowerShell. Do not use Command Prompt, Git Bash, or WSL for a block labelled PowerShell.
    • macOS: press Command+Space, type Terminal, and press Return. The Terminal application starts zsh automatically.
    • Linux: open Terminal from the applications menu. The Terminal application normally starts Bash automatically.

    The prompt is the text beside the blinking cursor. Check the stated computer, paste only the command after its prompt, press Enter, and wait for the prompt to return. For an Euler command, connect to Euler first; the same text window then controls the remote Euler computer.

    How to open a terminal and run a command

    A Python environment is a separate Python interpreter and package set for one project. Euler is a different computer from your laptop, so the environment is created again on Euler from the project's recorded dependency file.

    Goal: create reproducible Python environments for Euler jobs without copying a laptop environment or filling unsuitable storage with small files.

    Prerequisites: working ssh euler access and a project dependency definition such as environment.yml, requirements.txt, or pyproject.toml.

    New to text commands? Read how to open a terminal and run one command before using a command block. It explains the labels used below and what to copy.

    Execution context: inspection and the small training environment run on an Euler login node - Bash. Use a CPU allocation or batch job for dependency installation that compiles code, transfers substantial data, or performs meaningful computation.

    The Rule#

    Your laptop and Euler need separate environment directories. Commit the small text file that defines dependencies; do not commit or copy .venv, env, or a Conda installation directory.

    For the Passport exercise:

    • use the dated Python module named by the mission;
    • keep the small training environment in $HOME/passport-euler/venvs/passport-python;
    • load the module and activate the environment inside every Slurm script;
    • never use sudo or install project packages into the shared module or Conda base environment.

    The mission checks an existing target before creating anything and never deletes or overwrites it. Follow that guided recipe rather than copying a second command sequence from this reference page.

    Storage Choice#

    $HOME is backed up but has a limited quota and is appropriate only for small environments. Euler scratch is temporary. The shared Lustre work filesystem is not recommended for Conda environments because an environment contains many small files. For large dependency stacks, use the project-approved container workflow or ask for the project’s established environment location.

    Check environment size periodically:

    du -sh "$HOME/passport-euler/venvs/passport-python"

    This command only measures the training environment. Do not delete an environment merely because it is larger than expected; identify its owner and dependencies first.

    Inside A Slurm Script#

    The batch script must declare the software context before the application:

    module purge
module load stack/2024-06 python/3.11.6
. "$HOME/passport-euler/venvs/passport-python/bin/activate"
python your_script.py

    Do not rely on whichever environment happened to be active when sbatch was typed. Record the module version, dependency definition, Git revision, command, and relevant application configuration with the run.

    Project Dependencies#

    The Passport environment deliberately installs no project package. For a real project:

    1. inspect the committed dependency definition and project instructions;
    2. load the documented module and activate the project environment;
    3. install exactly the reviewed dependencies;
    4. run the project’s smallest verification command;
    5. record any resolved lock file or version snapshot required by the project.

    If installation fails, fix the dependency or platform problem. Do not request more job memory or a GPU to hide an import error.

    Source And Freshness#

    The training module stack/2024-06 with python/3.11.6 was verified on Euler on 2026-09-05. Recheck it with module spider python when preparing a new Passport release. Storage guidance follows the ETH Euler Conda and storage documentation; those primary sources take precedence when the cluster changes.
