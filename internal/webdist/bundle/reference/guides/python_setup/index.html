    Python Environments With Miniforge

    Goal: create isolated, reproducible Python environments locally and use the project's declared setup instead of accumulating packages in one global Python.

    View exact sourceReturn to my dashboard

    Goal: create isolated, reproducible Python environments locally and use the project's declared setup instead of accumulating packages in one global Python.

    Prerequisites: know whether the project already declares Python and package versions in pyproject.toml, environment.yml, or another setup file.

    Execution context: install and run Conda on your own computer. Use Windows PowerShell, macOS zsh, or Linux Bash from the exact project root named by the current step.

    The canonical practical exercise is Reproducible Python Environment.

    Mental Model#

    • Miniforge installs the conda/mamba environment managers with conda-forge.
    • An environment isolates a Python interpreter and packages for one project.
    • conda is useful for Python and binary/system dependencies.
    • python -m pip installs Python packages into the currently selected Python.
    • The repository, not an agent's chat history, declares how to recreate the environment.

    Do not install project packages into Conda base, the operating-system Python, or with sudo pip.

    Before Installing Anything#

    Run:

    conda --version
conda info --base

    If both commands work, keep that installation and skip all installation sections below.

    On Windows, if PowerShell says that conda is unknown, search the Start menu for Miniforge Prompt, Miniconda Prompt, or Anaconda Prompt before downloading anything. If one exists, open it and run the two checks above. If they work, run this once in that prompt:

    conda init powershell

    Close only that setup terminal, keep the terminal running the Passport open, open a new PowerShell window, and repeat the checks. If more than one Conda prompt or installation appears, stop and choose one with setup help; do not uninstall or overwrite either copy.

    On macOS or Linux, the Passport mission checks common personal installation folders and runs conda init for the selected shell when it finds exactly one existing installation. The change applies to a newly opened terminal, not the terminal that ran the command. Close that command terminal, open a new one, return to the practice folder, and repeat conda --version and conda info --base. If the check finds more than one installation, stop and choose one with setup help. Only install Miniforge after the check prints no-common-conda-installation.

    Install Miniforge On Windows#

    Execution context: Windows laptop - browser and Miniforge Prompt.

    Complete the checks above first. If no existing Conda installation or Start menu prompt was found:

    1. Download the Windows x86-64 installer from the official Miniforge repository.
    2. Choose Just Me and an installation path without unusual characters.
    3. Keep Start Menu shortcuts. Do not force-add Miniforge to the global Windows PATH when the installer warns about conflicts.
    4. Open Miniforge Prompt.

    Verify:

    conda --version
conda info --base

    Expected result: conda reports a version and the base path points to your personal Miniforge installation.

    To use Conda from PowerShell, run conda init powershell once from Miniforge Prompt, close every PowerShell window, and open a new one.

    Install Miniforge On macOS#

    Execution context: local macOS Terminal using zsh.

    Run this only after the existing-installation check prints no-common-conda-installation. This complete block detects the Mac architecture, downloads the matching official installer and published checksum into a new temporary directory, verifies the checksum, and removes only those temporary files when it exits.

    (
set -eu
temporary="$(mktemp -d "${TMPDIR:-/tmp}/ideal-passport-miniforge.XXXXXX")"
installer="$temporary/Miniforge3.sh"
checksum="$temporary/Miniforge3.sh.sha256"
cleanup() { rm -f -- "$installer" "$checksum"; rmdir -- "$temporary" 2>/dev/null || true; }
trap cleanup EXIT HUP INT TERM
asset="Miniforge3-MacOSX-$(uname -m).sh"
printf 'Operating system: '; uname -s
printf 'Architecture: '; uname -m
command -v curl >/dev/null || { printf 'STOP: curl is unavailable; use the official installer link.\n' >&2; exit 1; }
curl -fL --output "$installer" "https://github.com/conda-forge/miniforge/releases/latest/download/$asset"
curl -fL --output "$checksum" "https://github.com/conda-forge/miniforge/releases/latest/download/$asset.sha256"
expected="$(awk '{print $1}' "$checksum")"
actual="$(shasum -a 256 "$installer" | awk '{print $1}')"
[ "$actual" = "$expected" ] || { printf 'STOP: checksum mismatch. Do not run the installer.\n' >&2; exit 1; }
printf 'checksum-ok\n'
bash "$installer"
)

    Choose the personal default installation unless an existing path is reported. Answer yes when asked to initialize zsh. Then close only that setup Terminal, keep the terminal running the Passport open, open a new one, and run:

    conda --version
conda info --base

    Install Miniforge On Linux#

    Execution context: local Linux terminal using Bash.

    Run this only after the existing-installation check prints no-common-conda-installation. Do not use sudo.

    (
set -eu
temporary="$(mktemp -d "${TMPDIR:-/tmp}/ideal-passport-miniforge.XXXXXX")"
installer="$temporary/Miniforge3.sh"
checksum="$temporary/Miniforge3.sh.sha256"
cleanup() { rm -f -- "$installer" "$checksum"; rmdir -- "$temporary" 2>/dev/null || true; }
trap cleanup EXIT HUP INT TERM
asset="Miniforge3-$(uname -s)-$(uname -m).sh"
printf 'Operating system: '; uname -s
printf 'Architecture: '; uname -m
command -v curl >/dev/null || { printf 'STOP: curl is unavailable; use the official installer link.\n' >&2; exit 1; }
curl -fL --output "$installer" "https://github.com/conda-forge/miniforge/releases/latest/download/$asset"
curl -fL --output "$checksum" "https://github.com/conda-forge/miniforge/releases/latest/download/$asset.sha256"
expected="$(awk '{print $1}' "$checksum")"
actual="$(sha256sum "$installer" | awk '{print $1}')"
[ "$actual" = "$expected" ] || { printf 'STOP: checksum mismatch. Do not run the installer.\n' >&2; exit 1; }
printf 'checksum-ok\n'
bash "$installer"
)

    Choose the personal default installation unless an existing path is reported. Answer yes when asked to initialize Bash. Then close only that setup terminal, keep the terminal running the Passport open, open a new one, and run:

    conda --version
conda info --base

    If the script reports an unsupported asset, existing destination, missing checksum tool, or checksum mismatch, stop. Use the official Miniforge releases and request help rather than guessing a filename or overwriting an installation.

    Create A Project-Local Conda Environment#

    Execution context: local terminal at the repository root after Conda initialization.

    The Passport training project uses .venv as a project-local Conda prefix. Despite the folder name, it is a Conda environment, not one created with python -m venv.

    The committed definition is the setup contract:

    channels:
  - conda-forge
  - nodefaults
dependencies:
  - python=3.11

    nodefaults prevents a learner's personal Conda configuration from silently adding another package channel. A real project may pin more dependencies, but it should still document its channel policy and Python version.

    Use the Create A Reproducible Python Environment mission for the exact Windows, macOS, or Linux commands. It enforces this order:

    1. read the committed definition;
    2. inspect .venv without changing it;
    3. keep it only if it is a real directory, a Conda environment, and uses the declared Python version;
    4. stop on a file, symbolic link, junction, incomplete environment, or version mismatch rather than deleting it;
    5. prove .venv/ is ignored by Git;
    6. create it from environment.yml only when absent;
    7. activate it by its local prefix;
    8. print sys.executable, the Python version, and the pip location;
    9. select that same interpreter in the editor.

    The Git-ignore check must succeed before the creation command:

    git check-ignore -v --no-index .venv/conda-meta/history

    Expected: Git prints the rule covering .venv/. If it prints nothing, stop and correct .gitignore before creating the environment.

    The creation command is:

    conda env create --prefix ./.venv --file environment.yml -y

    Do not run it until the preceding inspection and Git-ignore checks pass. Do not remove or replace an existing .venv merely to make the command succeed.

    After activation, verify the interpreter rather than trusting the prompt:

    conda activate ./.venv
python -c "import sys; print(sys.executable); print(sys.version)"
python -m pip --version

    All reported paths must belong to this repository's .venv. Install the real project only with the command documented by that project. Never improvise a second installer, install into Conda base, or use sudo pip to bypass an environment problem.

    Record Reproducibility#

    Prefer a project contract containing:

    File Purpose
    pyproject.toml Package metadata, Python dependencies, tests/lint configuration
    environment.yml Conda interpreter and binary dependencies when needed
    requirements.txt Optional pip-only input/snapshot for simple projects
    README.md One setup command and one verification command

    An environment export can contain platform-specific transitive packages. Review it before committing and prefer a concise hand-maintained environment file when possible.

    VS Code#

    1. Open the project folder.
    2. Run Python: Select Interpreter from the Command Palette.
    3. Select the interpreter whose path is inside the project's .venv folder.
    4. In the integrated terminal, run:
    python --version
python -m pip --version

    For notebooks, select the same environment in the kernel picker.

    Euler Python Environment#

    Do not copy a local environment directory to Euler. Create an Euler-native virtual environment using an available software stack. Follow the Passport mission first, then use the Euler Python environment reference for project-specific work. It explains storage, module loading, batch-script activation, dependency installation, and recovery without duplicating a second setup recipe here.

    For GPU Python, use the python_cuda/3.11.6 module only when the project needs that toolchain and after checking current availability:

    module spider python_cuda/3.11.6

    PyTorch And CUDA#

    PyTorch wheel and CUDA combinations change. Do not preserve a copied wheel URL as permanent lab policy.

    1. Create/activate a clean project environment.
    2. Open the official PyTorch installation selector.
    3. Select the actual operating system, package manager, language, and CPU/CUDA platform.
    4. Run the generated command in the intended environment.
    5. Record the selected versions in project configuration or documentation.

    On Euler, perform the install/setup in a CPU allocation when it is substantial; request a GPU only for the actual GPU verification.

    Verification inside an allocated GPU job:

    python - <<'PY'
import torch

print("torch:", torch.__version__)
print("runtime CUDA:", torch.version.cuda)
print("CUDA available:", torch.cuda.is_available())
if torch.cuda.is_available():
    print("GPU:", torch.cuda.get_device_name(0))
PY

    Detecting a GPU is a smoke test, not evidence that training uses it efficiently. Follow the Euler GPU Track.

    AI-Agent Reproducibility#

    Safe inspection prompt:

    Goal: explain how this Python project is recreated and verified.
Context: inspect README, pyproject.toml, environment files, and tests.
Constraints: do not install packages or edit files; do not read .env or secrets.
Verification: identify exact commands supported by repository evidence.
Output: missing reproducibility information and the smallest patch plan.

    Ask why each new dependency is needed. Do not let an agent update many packages "just in case" or claim compatibility without running the project checks.

    Common Failures And Safe Recovery#

    • conda not found: open Miniforge Prompt or initialize the current shell, then restart it.
    • Wrong interpreter: reactivate the environment and reselect it in VS Code.
    • pip installs elsewhere: compare python -m pip --version with the selected Python path.
    • Environment works only on one machine: recreate from declarations and document missing platform/system requirements.
    • CUDA unavailable: compare driver, selected PyTorch build, allocation, and device placement; do not install random CUDA versions into the same env.

    Verification#

    • Environment creation and installation follow project-owned files.
    • Tests or the documented smoke check run in a newly created environment.
    • git status --short does not show an environment, cache, or generated data.
    • GPU package instructions came from the current official selector.

    Ask For Help When#

    Dependency declarations conflict, private packages lack documented access, binary/CUDA compatibility is unclear, or installation requires global changes.
