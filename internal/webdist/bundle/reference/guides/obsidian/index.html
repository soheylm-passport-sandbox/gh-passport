    Obsidian (Optional Handbook View)

    Goal: open one clean handbook clone as an Obsidian vault without changing Passport progress or committing local Obsidian state.

    View exact sourceReturn to my dashboard

    Goal: open one clean handbook clone as an Obsidian vault without changing Passport progress or committing local Obsidian state.

    Prerequisites: both Passport Git missions pass and your GitHub account can read IDEALLab/onboarding-IT.

    Execution context: Obsidian and Git run on your own computer. Do not run these commands on Euler or Blade.

    Obsidian is an optional way to read the handbook after Git is working. It is not required for the Passport, Git work, Python, Euler, NAS, or Blade.

    Before You Start#

    Complete both Passport Git missions first:

    1. Set Up Git And GitHub Safely
    2. Make And Review A First Pull Request

    You should already be able to run gh auth status and git status. If either command fails, return to the Git mission instead of troubleshooting Obsidian.

    1. Check GitHub Access#

    Where: your computer, in PowerShell on Windows or a terminal on macOS/Linux.

    gh auth status --active --hostname github.com
gh repo view IDEALLab/onboarding-IT --json nameWithOwner --jq .nameWithOwner

    Expected: the second command prints IDEALLab/onboarding-IT.

    If access is denied, stop. Accept the lab's GitHub invitation or ask for repository access. Do not put a token in a clone URL.

    2. Clone One Handbook Copy#

    Choose a normal local parent folder that is not inside OneDrive, iCloud, Dropbox, an existing Git repository, or another Obsidian vault. Then run:

    gh repo clone IDEALLab/onboarding-IT onboarding-IT-handbook
cd onboarding-IT-handbook
git status --short --branch

    IDEALLab/onboarding-IT is the GitHub repository. onboarding-IT-handbook is only the name of the new folder on this computer.

    Expected: the final command reports a branch and no local changes.

    If onboarding-IT-handbook already exists, the clone command stops. Do not delete or overwrite it. Enter that folder, run git status --short --branch, and keep it only if Git identifies it as the expected repository.

    3. Install And Open Obsidian#

    1. Install Obsidian from https://obsidian.md/download.
    2. Open Obsidian.
    3. Select Open folder as vault.
    4. Select the onboarding-IT-handbook folder itself.
    5. Open README.md.

    The vault root is the folder that directly contains README.md, .gitignore, and onboarding_IT_guides. Do not select its parent folder or only onboarding_IT_guides.

    Expected: README.md renders and its local links open other handbook pages. Continue your assigned Passport in the browser; Obsidian is not a second progress tracker.

    4. Keep Obsidian State Local#

    Obsidian creates a .obsidian folder for local settings. This repository ignores it. Verify the rule:

    git check-ignore -v --no-index .obsidian/workspace.json
git status --short

    Expected: the first command names a .gitignore rule and the second does not list .obsidian.

    Do not force-add .obsidian, workspace layouts, caches, or personal notes. Do not put confidential project notes in this handbook clone.

    5. Update The Handbook#

    From the onboarding-IT-handbook folder:

    git status --short
git pull --ff-only

    Run the pull only when the first command prints nothing. If it lists changes, inspect them before updating. Do not use a hard reset to discard work.

    Verification#

    • gh repo view names IDEALLab/onboarding-IT.
    • The opened vault root contains README.md.
    • git status --short does not list .obsidian.
    • The Passport still resumes with gh passport open, independently of Obsidian.

    If Blocked#

    • Wrong or empty vault: reopen the folder that directly contains README.md.
    • Clone denied: resolve the GitHub invitation or repository access first.
    • Folder already exists: inspect it; do not clone on top of it.
    • Obsidian files appear in Git: stop before committing and verify the ignore rule. Unstage the files without deleting your local settings.
    • Pull refuses: inspect the local diff and request help; do not force-pull or hard-reset.

    Ask For Help When#

    GitHub access is missing, Git identifies a different repository, the correct vault root remains unclear, or updating would overwrite unexplained local changes. Share only the repository name and sanitized Git error, not private notes or credentials.
