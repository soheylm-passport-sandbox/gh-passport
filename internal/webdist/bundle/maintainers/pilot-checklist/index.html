    Pilot And Human Validation Checklist

    Goal: prove the passport works for a person without maintainer privileges, not only for the author or CI.

    View exact sourceReturn to my dashboard

    Goal: prove the passport works for a person without maintainer privileges, not only for the author or CI.

    No learner cohort is currently available. The automated and synthetic release gate is recorded in Automated Validation; unchecked items here remain future human-only evidence and do not block implementation. Run this checklist before claiming measured learner usability, after material authentication or Euler changes, and after recurring confusion. Use fictional or harmless content. Never record credentials, private keys, confidential data, or unnecessarily broad student logs.

    1. GitHub Front Door And First Pull Request#

    Test with a non-admin lab member who has not configured the repository before:

    • The public README is readable before Git, Python, an editor, Obsidian, or organization membership is required.
    • From that page, the learner installs only Git and GitHub CLI, then runs the documented gh auth login, extension install, and gh passport start commands one at a time.
    • gh passport start creates or reuses the learner-owned public fork, onboarding/<username> branch, canonical route, and one central draft PR.
    • Responsibility questions resolve dependencies rather than using a degree or job title, and the learner sees the route before starting the first task.
    • The learner understands that the fork and PR are public and submits only fictional, sanitized exercise content.
    • After a break, gh passport open resumes local navigation and the latest controller-verified IDEAL Lab IT Passport Check Run reconstructs official progress.
    • Deleting .passport-local/ or using a fresh clone loses preferences only; an explicit sync reconstructs the official current mission.
    • Windows/macOS platform branches, expected results, blocked paths, and checkpoint evidence work without maintainer translation.
    • Mission Markdown remains a complete no-launcher fallback; no browser page claims to save official evidence or completion locally.
    • The selected platform preflight reports missing tools and malformed SSH configuration without changing files.
    • Git installation/authentication precedes automatic fork/clone and PR work; Python setup occurs only for a Python responsibility.
    • GitHub CLI browser authentication and HTTPS clone work without a PAT or an SSH key; editor installation is taught only when the route needs it.
    • The launcher-created onboarding/<username> branch receives learner commits; the learner does not merge or close the assessment PR.
    • Opening the clone from main stops with one safe git switch command; it never silently displays or submits work from the wrong branch.
    • The documented local checks and GitHub Actions run as described.
    • They use a Conventional Commit, push to the existing draft PR, and do not open, merge, or close a second assessment PR.
    • Before the controller reports, the dashboard says Waiting for automatic check, shows Not checked, and tells the learner not to push again.
    • If an unmerged PR is closed accidentally, rerunning gh passport start preserves the route and branch and creates one replacement draft PR.
    • A merged PR stops automatic recovery and directs the learner to private asynchronous help; public main protection prevents this in normal use.

    Current deployment facts:

    • Public passport-exercises permits protected main on GitHub Free. Verify the live ruleset, required checks, disabled force pushes/deletions, and the learner's inability to merge before inviting a cohort.
    • The system does not depend on mutable FirstSteps; route-specific fixtures and hidden behavior checks are versioned with the curriculum.

    2. Fresh Windows SSH And VS Code Pilot#

    Use a Windows 10/11 computer with OpenSSH and VS Code. Include one pilot with an existing unrelated SSH host so preservation is tested:

    • Password login to Euler works before key generation.
    • The dedicated-key block creates id_ed25519_euler without overwriting another key.
    • Rerunning key generation prints STOP and changes no key file.
    • Windows ACL commands leave the private key accepted by OpenSSH.
    • Public-key installation sends only the .pub file.
    • The key-only test prints key-ok and never asks for the ETH password.
    • The Host euler include validates and the unrelated host still resolves to its original settings.
    • The generated tunnel host key and host block validate after a reboot/new PowerShell session; no earlier shell variables are required.
    • The local tunnel hostname test works before VS Code is opened.
    • VS Code installs/starts .vscode-server, opens the intended project, and reports a compute-node hostname plus SLURM_JOB_ID.
    • Stopping the tunnel removes the allocation.

    This Windows execution cannot be proven from macOS CI. A Windows CI runner proves parsing and launcher behavior, while this checklist remains the evidence needed before claiming measured Windows learner usability.

    3. macOS Or Linux SSH Pilot#

    • Repeat the dedicated-key, key-only, include-preservation, tunnel, and cleanup checks in a fresh local account or disposable SSH directory.
    • Confirm every generated private/config file has restrictive permissions.
    • Confirm malformed existing SSH configuration causes a stop before edits.

    4. Euler Low-Cost Operational Pilot#

    Do not start a GPU job merely to release documentation.

    • my_share_info shows the expected lab share for the test account.
    • sbatch --test-only accepts the tiny CPU, capped-array, explicit RTX 4090, explicit RTX 3090, and explicit RTX PRO 6000 (pro_6000) profiles.
    • The lab inventory still includes two RTX PRO 6000 GPUs, and current ETH CUDA compatibility guidance is reflected in the student warning.
    • The flexible rtx_3090,rtx_4090 request remains absent until a live test succeeds; it failed on 2026-08-04 despite appearing in ETH documentation.
    • With approval, one tiny CPU job completes and produces logs, sacct, and seff fields matching the lab.
    • A pilot can read a pending reason and cancel their own harmless test job.
    • Array evidence counts aggregate concurrency across every active array and ordinary job, not only one % cap.
    • $HOME, $SCRATCH, /cluster/work/fuge, module names, and quota commands still match current ETH documentation and read-only system checks.
    • Lab IT provisions a disposable shared project root before the owner tests child-directory setgid/default ACL inheritance with two accounts.
    • Local ParaView 6.0.0 loads a fresh ETH euler_600.pvsc, submits the documented conservative CPU allocation, opens harmless remote data, and releases the job when the client and launcher close.
    • The pilot does not infer GPU-rendering support from the CPU ParaView test.

    5. NAS And Blade Pilot#

    • On ETH network/VPN, Windows resolves \\d.ethz.ch\groups\mavt\ide\Projects\<SupervisorFirstName>.
    • macOS resolves the corresponding smb://d.ethz.ch/... path.
    • A new member can write only in the supervisor-approved username folder.
    • On Blade, P: maps to durable project storage and the documented supervisor/username folder exists.
    • A harmless file copied from temporary D: to P: remains after sign-out.
    • The pilot understands that C:, Desktop, Documents, Downloads, and D: are not the only durable copy.
    • Current installed Blade software and hardware claims are rechecked.

    6. External Assessment Security Pilot#

    The local implementation and mocks do not prove production GitHub App wiring. Before issuing assignments:

    • Confirm exactly four active IDEALLab repositories: private onboarding-IT, public passport-exercises, public gh-passport, and private onboarding-control.
    • Confirm the controller App is installed only on passport-exercises with read-only Contents and write Checks/Issues/Pull requests; its key exists only in onboarding-control.
    • Confirm the control workflow uses its own bounded GITHUB_TOKEN for private assignment and registry commits.
    • Confirm the organization has no payment method for the zero-cost pilot, or has a GitHub Actions product budget that stops usage at its limit; included-usage alerts alone are not a spending lock.
    • Confirm the controller runs automatically on the bounded daytime/night cadence, does not overlap itself, and leaves unchanged PRs unassessed.
    • Record private Actions usage after five synthetic learners and confirm the projected full-cohort usage remains below the included allowance.
    • Freeze immutable user, reviewer, fork, parent, base, PR, route, and passport.json identities before assessment.
    • Run untrusted code only in a bounded ephemeral environment with no write token, organization secrets, or unnecessary network access.
    • Prove a possible secret blocks before any matched content reaches an AI reviewer.
    • Prove a student cannot edit the protected rubric, reviewer prompt, workflow, baseline SHA, or endorsement authority.
    • Prove deterministic feedback, retry behavior, human approval, and private completion-record storage with a fictional learner.
    • Run two disjoint authority updates from stale clones and prove both are retained after safe fetch/rebase/push persistence.
    • Complete a live synthetic non-admin transaction from fork creation through exact-SHA Check Run, PR feedback, reviewer approval, and private record.

    7. Learning Pilot#

    Run one beginner and one experienced pilot:

    • Each selects only the tracks matching their responsibilities.
    • The beginner completes tasks without the maintainer translating jargon.
    • The experienced user can use the fast path without skipping lab policy.
    • Both can explain their evidence without an AI agent answering for them.
    • Record confusing step, expected behavior, observed behavior, severity, and resulting documentation issue.

    8. AI Agent Learning Pilot#

    Use only the generated fictional fixtures and a non-admin test learner:

    • The learner completes and commits the manual task before opening an agent.
    • GitHub Education and Copilot Student activate without checkout or a payment method, or the learner can continue manually while verification is pending.
    • VS Code signs into the intended personal GitHub account and a read-only request leaves the working tree unchanged.
    • The bounded task changes only the route's editable AI-agent fixture, and the learner reviews every line and proposed command.
    • The learner personally runs the unittest and application checks, plus Ruff/mypy/pre-commit only when the training repository declares their reproducible environment, and can explain accepted and rejected/revised suggestions.
    • The evidence omits prompts, account screenshots, keys, and protected data.
    • An optional Zed/OpenRouter pilot uses a consenting maintainer's personal account, disabled auto-recharge, a low dedicated key limit, fictional content, and immediate key revocation after testing.
    • Zed keychain storage and local OPENROUTER_API_KEY precedence behave as documented.
    • No student is directed to purchase credits or to use the lab-funded organization procedure from this repository.
